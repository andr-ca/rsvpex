# Quick Task 260711-8a8: Auto-Login New Hosts Immediately After Signup

## Summary

Implemented auto-login in the host signup flow. New hosts are now logged in immediately after successful signup and redirected to their dashboard (/rsvp/admin) with a 303 (See Other) status code, eliminating the friction of a redundant login step.

## Implementation

### Task 1: Auto-Login in POST /rsvp/admin/signup

**File:** `app/src/routes/adminSignup.ts`

Changes:
- Added imports: `setCookie` from 'hono/cookie', `createSession` from '../domain/adminAuth'
- Defined `SESSION_EXPIRY_DAYS = 7` at module level (matching adminLogin.ts pattern)
- After successful INSERT (when `result.meta.changes !== 0`):
  - Call `createSession(c.env.DB, id, SESSION_EXPIRY_DAYS)` to create a new session token
  - Set session_id cookie with secure attributes: `httpOnly: true`, `sameSite: 'Lax'`, `secure: true`, `maxAge: SESSION_EXPIRY_DAYS * 24 * 60 * 60`, `path: '/'`
  - Changed redirect from `c.redirect('/rsvp/admin/login?signup=success', 302)` to `c.redirect('/rsvp/admin', 303)`
- Error paths unchanged:
  - 409 duplicate email: Still renders error page, no session created
  - 400 validation error: Still renders error page, no session created

### Task 2: Integration Test Updates

**File:** `app/tests/integration/admin-signup.test.ts`

Updated the primary test case "creates a new host account with valid email and 12+ char password":
- Changed expected status from 302 to 303
- Changed expected Location header from containing '/rsvp/admin/login' to exactly '/rsvp/admin'
- Added session_id cookie extraction and verification from Set-Cookie header
- Added follow-up authenticated request to /rsvp/admin/ using the session cookie
- Verified follow-up request returns 200 (proving session is immediately usable)
- Updated two additional tests to expect 303 status code
